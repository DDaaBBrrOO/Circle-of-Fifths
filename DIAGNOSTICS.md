# 🔧 Обновления для диагностики ошибок сборки APK

## Что было добавлено

### 1. **Pre-build diagnostics** (Шаг 14)
Перед сборкой теперь выполняется:
- Список всех доступных Gradle задач
- Проверка зависимостей проекта
- Список вариантов сборки (build variants)
- **Dry-run** сборки для проверки конфигурации

### 2. **Улучшенная сборка** (Шаг 15)
- Показывает **exit code** сборки
- При ошибке выводит **последние 200 строк** лога
- Автоматически ищет строки с `error`, `failed`, `exception`
- Использует `--warning-mode all` для полного вывода предупреждений
- Добавлен `--no-build-cache` для чистой сборки

### 3. **Улучшенный поиск APK** (Шаг 16)
- Показывает **полную структуру** `build/outputs`
- Выводит **последние 200 строк** лога при отсутствии APK
- Автоматически ищет ошибки в логе

### 4. **Загрузка логов всегда** (Шаг 18)
- Логи загружаются **всегда**, а не только при ошибке
- Включает: `gradle-build.log`, `build/reports/`, все `build.gradle` файлы, `gradle.properties`
- Срок хранения: 7 дней

### 5. **Расширенная диагностика** (Шаг 13)
Добавлено:
- Проверка существования файлов с детальным выводом
- Вывод переменных окружения (`ANDROID_HOME`, `JAVA_HOME`, `PATH`)
- Версия Java
- Содержимое `gradle-wrapper.properties`
- Полная структура Android проекта

### 6. **Очистка кэша** (Шаг 12)
- Добавлена очистка `.gradle` директории
- Вывод структуры всех конфигурационных файлов

## Как использовать новую диагностику

### При ошибке сборки:

1. **Скачайте артефакт `gradle-logs`** из вкладки Actions
2. **Изучите файлы:**
   - `gradle-build.log` - полный лог сборки
   - `build/reports/` - отчёты Gradle
   - `build.gradle` - конфигурация проекта

3. **Посмотрите вывод шагов:**
   - Шаг 13: Проверка конфигурации
   - Шаг 14: Pre-build diagnostics
   - Шаг 15: Build APK (показывает последние строки при ошибке)
   - Шаг 16: Locate APK (показывает структуру при отсутствии файла)

### Ключевые моменты для анализа:

1. **Exit code** в шаге 15 показывает, упала ли сборка
2. **Последние 200 строк** лога обычно содержат причину ошибки
3. **Dry-run** в шаге 14 показывает, какие задачи должны выполниться
4. **Переменные окружения** в шаге 13 помогают проверить конфигурацию SDK

## Примеры типичных ошибок и их диагностика

### Ошибка: `Could not find com.android.tools.build:gradle`
**Где искать:** Шаг 13 → "Root build.gradle"
**Решение:** Проверьте версию AGP и репозитории

### Ошибка: `SDK location not found`
**Где искать:** Шаг 13 → "Environment Variables"
**Решение:** Проверьте `ANDROID_HOME` и `local.properties`

### Ошибка: `Execution failed for task ':app:mergeDebugResources'`
**Где искать:** Шаг 15 → "Last 200 lines of build log"
**Решение:** Обычно проблема в ресурсах Android, проверьте `app/src/main/res/`

### Ошибка: `AAPT: error: resource not found`
**Где искать:** Шаг 16 → "Error lines from log"
**Решение:** Проверьте наличие всех ресурсов в `app/src/main/assets/public/`

## Локальная отладка

Если проблема не решается через GitHub Actions:

```bash
# Запустите локальную сборку с полной диагностикой
chmod +x scripts/build-apk-local.sh
./scripts/build-apk-local.sh debug 2>&1 | tee local-build.log

# Или вручную с максимальной детализацией
cd android
./gradlew assembleDebug --no-daemon --stacktrace --info --debug 2>&1 | tee debug-build.log
```

## Что делать дальше

1. **Запустите workflow снова** - теперь вы получите гораздо больше информации
2. **Скачайте артефакт `gradle-logs`** - там будут все логи и конфигурации
3. **Изучите вывод шагов** - особенно шаги 13, 14, 15, 16
4. **Поделитесь логами** - если проблема не решается, прикрепите `gradle-build.log` к issue

## Дополнительные возможности

- **Dry-run** показывает, какие задачи будут выполнены, без фактической сборки
- **Полный список задач** помогает понять, какие команды доступны
- **Зависимости проекта** показывают, какие библиотеки используются
- **Переменные окружения** помогают проверить правильность настройки SDK
